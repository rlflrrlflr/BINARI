## 3. 진짜 발명은 '궁합'이 아니라 '지도'다

카피 원문(1차):
> **"강석우님의 귀인 지도"**
> **"생일만 넣으면, 내가 이 사람에게 어떤 사람인지 나와요 — 지도에 이름 올려보세요."**

**① 방향을 뒤집었다.** 일반 궁합은 "우리 둘이 맞나"인데 이건 **"내가 저 사람에게 어떤 존재인가"**다. 상대 평가가 아니라 **내 위치 확인**이라 **직장 관계에도 쓸 수 있다.** (창업자 실제 경험: 팀원이 "팀장님은 어떤지 궁금해요!"로 링크를 던짐 — 연애 궁합이면 나올 수 없는 문장.) **관계 궁합을 직장까지 확장한 것이 이 서비스의 첫 수.**

**② 1회성 이벤트를 컬렉션으로 바꿨다.**

| | 일반 궁합 | 귀인 지도 |
|---|---|---|
| 구조 | A+B → 결과 1개 → 끝 | A + (B,C,D,E…) → **자라는 자산** |
| 다시 볼 이유 | 없음 | **지도가 채워짐** |
| 링크 던질 이유 | 1회 | **계속** |

→ **바이럴 장치와 리텐션 장치를 하나로 합쳤다.** 덱이 "8개사 최대 약점은 리텐션"이라 지목한 자리를 같은 장치로 덮는다.

**③ 던지는 쪽 마찰이 0.** A는 아무것도 입력하지 않는다. 링크만 던진다. 넣는 건 B이고, B는 강요가 아니라 **궁금해서** 넣는다.

**④ 참여를 '수집'으로 프레이밍.** "지도에 이름 올려보세요" — 부탁이 아니라 초대다.

## 4. 루프

```
A가 지도를 만든다 (입력 최소)
   ↓ 링크를 던진다          ← A는 추가 입력 없음, 마찰 0
B가 자기 생일을 넣는다        ← 자발
   ↓
A의 지도에 B가 추가된다       ← A의 자산이 자람 → A가 또 던짐
   ↓
B가 결과를 본다 → "그럼 저 사람은?"  ← B도 자기 지도를 만듦
   ↓
B가 링크를 던진다 → 루프 재시작
```

**이것이 '강한 루프'의 실물이다** — 결과를 **이미지로 캡처해 보내는** 약한 루프(K≈0)와 달리, **링크를 받은 사람이 반드시 방문·입력해야** 성립한다.

## 5. 링크 카드까지 설계돼 있다 (HTML 1차 확인)

- OG 이미지가 **슬러그별 동적 생성** — `/n/{slug}/opengraph-image`, 1200×630 PNG
- 카드 제목이 **"강석우님의 귀인 지도"** — 받는 사람 눈에 **누구 것인지** 먼저 보인다
- 카드 설명에 **행동 지시가 들어 있다** — "생일만 넣으면… 지도에 이름 올려보세요"
- → **클릭 전에 이미 할 일을 안다. 공유 카드가 랜딩 역할을 한다.**
- `robots: index, follow` — **개인 페이지를 색인시킨다.** 유저가 늘수록 검색 유입 면적이 자동 확대. 운세위키의 `/birthyear/*` 대량 랜딩과 같은 수법을 **유저가 대신 생성**하는 형태. **획득 채널 둘이 한 행동에 얹혀 있다.**

## 7. 개인정보 — 직전 세션의 내 판단을 정정한다

2026-08-02 앞선 답변에서 "**상대가 직접 입력하면 제3자 수집이 아니라 본인 제공이 되어 법적으로 깨끗해진다**"고 썼다. **절반만 맞다. 수집은 정리되지만 제3자 제공이 남는다.**

| 단계 | 성격 | 근거 |
|---|---|---|
| B가 자기 생일 입력 | 본인 제공 → **동의만 받으면 됨** | 개인정보보호법 제15조 |
| **결과가 A의 페이지에 표시됨** | **B의 정보가 A에게 감 = 제3자 제공** | **제17조 — 별도 동의 필요** |
| B가 14세 미만 | 법정대리인 동의 | 제22조의2 |

**사주도령은 사업자등록·통신판매업 신고를 했다.** 법을 아예 안 챙긴 곳이 아니다. 창업자 관찰대로 동의를 안 받는다면 **빠진 건 정확히 위 두 번째 줄**로 보인다.
**단 창업자가 본 것은 링크를 받은 페이지다. 입력 화면의 동의 체크 유무는 미확인** — 팀이 실제로 넣어보면 5초에 확인된다.

## 8. 비나리 대조 — 뼈아픈 것

| 리포에 써둔 것 | 사주도령이 한 것 |
|---|---|
| "비나리 최대 약점은 **획득**" | **제품 구조 자체를 유통 채널로** 만듦. 광고비 아님 |
| "수호신 = 복제 못 하는 소유물" | 귀인 지도도 소유물. **차이 — 수호신은 혼자 갖고, 지도는 남을 끌어들인다** |
| 헌장 "모를 권리 — push 금지" | **push 없음. 다른 사람이 대신 당긴다.** 헌장을 안 깨고 확산 |
| 덱 검증 "돈이 도는 축은 관계, 진로 아님" | **그 결론의 실물 증거** |
| 부적 내보내기 = **이미지** | **링크.** 같은 '공유'인데 구조가 다르다 |

**가장 아픈 한 줄**: 비나리는 리텐션 자산 5종을 만들고 3종에 계측조차 안 붙였으며 작동 실적이 1명이다. 사주도령은 **바이럴과 리텐션을 한 장치로 합쳐서** 돌린다.

## 9. 헌장을 안 깨는 비나리 형태 (설계 가설 — 미검증)

```
A가 고민을 판결받는다
   ↓ "이 결정, 다른 사람의 수호신은 어떻게 볼까?"   ← A가 당김. push 아님
링크를 던진다                                    ← A는 추가 입력 없음
B가 자기 생년월일을 넣는다                          ← 본인 제공. 남의 실명 안 받음
   ↓
A의 판결 페이지에 "B의 수호신이 본 이 결정"이 쌓인다
```

| 헌장 | 충돌 |
|---|---|
| 질문 원문·실명 미전송 | **안 깸** — B가 직접 입력, 질문 원문은 미전송 유지 |
| 모를 권리(push 금지) | **안 깸** — A가 당기고 B가 자발 |
| 판결문 형식 보존 | **안 깸** — 축·카드 수 불변 |
| 계측 | **제3자 제공 동의를 새로 받아야 함**(제17조) |

→ **판결이 1인 이벤트에서 N인 컬렉션이 된다.** 획득과 리텐션을 같은 장치로 건드린다.
