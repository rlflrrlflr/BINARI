## 1. 지금 상태 — 코드 실측 (앞선 추정 정정)

먼저 정정한다. 코드 주석(§1327)은 궁합을 *"각인의 애드온 — 내 명식이 이미 있어야 열린다"* 라고 적고 있지만,
**실제 화면에서는 각인과 궁합이 로비의 나란한 두 버튼이다.**

| 항목 | 실측 |
|---|---|
| 탭 | **없다.** 판결 로비 하나 + 모달들 |
| 각인 진입 | 로비 버튼 `setImprintOpen(true)` (App.jsx §4821) |
| 궁합 진입 | 로비 버튼 `setMatchOpen(true)` (§4824) — **각인 모달 안이 아니다** |
| 노출 조건 | 둘 다 `!ritual && !res && saju` — 판결 전 로비에서만 |
| 상태 | `imprintOpen` / `matchOpen` 두 boolean, 형제 관계 |

**이 정정이 계획을 바꾼다.** 궁합을 탭으로 옮기는 건 결제 구조 수술이 아니라 **버튼 하나를 다른 화면으로 옮기는 일**이다.
`MatchDoc` 은 이미 자기 완결 컴포넌트(`saju`, `birth`, `onClose`)라 부모만 갈아 끼우면 된다.
비용이 낮으므로 §6의 순서에서 궁합 이동을 뒤로 미룰 이유도 줄었다 — 다만 **곁이 먼저 있어야 한다**는 이유는 그대로다(§6).

**없는 것**: 탭 자체 · 곁이라는 개념 · 관계 화면의 수호신(인계서 §1) · 재방문 컨텍스트를 담을 자리.

## 2. 왜 두 탭인가 — 두 국면의 성격이 정반대다

| | **판결** 탭 | **곁** 탭 |
|---|---|---|
| 성격 | 일회성 · 사적 · 무거움 | 누적 · 보여줄 만함 · 가벼움 |
| 설계 헌장 | **모를 권리** — 시스템이 먼저 펼치지 않는다 | **알 권리** 쪽 — 있는 건 다 보여준다 |
| 여는 이유 | 고민이 생겼을 때 | **아무 일 없어도** |
| 자산 | 판결록(과거형) | 곁(현재형, 계속 변함) |

한 화면에 둘을 같이 두면 **모를 권리와 알 권리가 같은 자리에서 충돌한다.** 지금 로비가 정확히 그 상태다 —
"두드려봐, 답은 거기 있어"(먼저 안 펼침) 옆에 각인·궁합 상품 버튼 두 개가 상시 붙어 있다.

그리고 D7 게이트 관점에서 이게 구조적 약점이다. 판결은 **수요가 있을 때만** 열리는 물건이고,
습관은 수요가 없을 때도 열리는 물건에서만 생긴다. 곁은 후자를 만들 수 있는 유일한 축이다
(수호신·판결 포맷·되물음 셋 중 **되물음=재방문 컨텍스트**에 해당).

## 3. 어휘 — 「곁」

**탭 이름은 「곁」.**

| 근거 | 내용 |
|---|---|
| 그림과 글자가 같은 말을 한다 | 시안의 시각 문법이 *궤도를 도는 빛* 이다. 곁 = 옆에 있는 자리. 이름과 형상이 어긋나지 않는다 |
| 연애로 안 좁혀진다 | 궁합 화면이 이미 *"연인만이 아니야 — 같이 일하는 사람, 가족, 동업자에게도"* 라고 말한다. 탭 이름이 그걸 배신하면 안 된다 |
| 소유가 아니라 **위치**를 말한다 | 수호신은 내 것, 곁은 옆에 선 것. 두 형상 합성 금지(인계서 §3 원칙 1)와 어긋나지 않는다 |
| 순우리말·두 글자 | 하단 탭 라벨로 들어간다 |

### 기각한 후보

| 후보 | 기각 사유 |
|---|---|
| **인연** | ①사주앱 클리셰라 차별점이 안 된다 ②전제 (D) *"대규모 풀 → 글로벌 인연 매칭"* 을 **현재 형태로는 불가능**으로 판정하고 로드맵에서 제거했다. 그 단어를 화면에 박으면 **기각한 방향이 이름으로 되살아난다** |
| **귀인** | 경쟁사 「귀인지도」와 정면 충돌 |
| **연(緣)** | 한 글자 한자 단독은 읽기가 애매 |
| **사이** | 탭 라벨로는 조사가 안 붙는다("사이 탭"). **다만 관계 자체를 부르는 말로는 채택** — 인계서가 이미 *"우리는 사이를 그린다"* 로 쓰고 있다 |

### 확정 어휘 한 벌

| 자리 | 말 | 쓰지 말 것 |
|---|---|---|
| 탭 이름 | **곁** | 친구 · 인연 · 관계 |
| 한 사람 | **곁 하나** / 곁에 선 사람 | 슬롯 · 카드 · 멤버 |
| 부르는 행위 | **곁에 부른다** | 초대하기 · 친구 추가 |
| 둘 사이 | **사이** | 궁합도(度) · 점수 |
| 유료 문서 | **궁합** (그대로 둔다) | — |

궁합만 기존 이름을 유지한다. 검색성과 즉시 이해도가 자산이고, 이건 **문서 이름**이지 화면 이름이 아니다.

## 4. 화면 구조

```
┌──────────────────────────────┐
│                              │
│      (현행 화면 그대로)        │   ← 판결 탭: 아무것도 안 바꾼다
│                              │
├──────────────────────────────┤
│   판결          곁            │   ← 하단 탭 2개
└──────────────────────────────┘
```

### 곁 탭 — 층 세 개

**1층 · 내 수호신 (항상 있다)**
곁이 0이어도 이 층이 화면을 완결시킨다. 빈 슬롯·진행바·"0명" 표기 **금지**.
곁이 생기면 §곁 시안 그대로 궤도에 빛이 선다.

> ⚠️ **크기 규칙 — v01 정정(v132.1)**
> 이 문서를 넘길 때 구두로 *"곁 탭은 뒤로 물러난다"* 고 말했고 그대로 구현됐다. **그 지시는 폐기한다.**
> 곁 탭만 작은 값(`vh*0.5`/캡 600, 확대율 없음)을 쓴 결과 실측 **466px — 판결(719px)의 65%** 가 되어
> 창업자 지적을 받았다("판결도 곁도 수호신이 너무 작게 보여").
> 다시 재 보니 **궤도 반경은 본체의 1.05배**뿐이다(곁 시안 실측). 물러날 이유가 거의 없었다.
>
> - **판결·곁은 같은 size 식을 쓴다** — `min(vw*1.1, vh*0.57, 640)`
> - 여유는 **CSS 확대율로만** 준다 — 판결 `1.85` / 곁 `1.72`(`.halo.wide.lobbyscale` / `.gyeotscale`)
> - ⚠️ **`size`(backing 해상도)를 키워서 해결하지 마라.** 확대율은 컴포지터가 처리해 렌더 비용이 0이지만,
>   `size` 를 키우면 프래그먼트가 제곱으로 늘어난다 — 입자 27,000개 × 가산 블렌딩 4패스라 v127.1 인장 렉이 재발한다.
>
> 수호신이 탭마다 다른 크기로 보이면 **같은 존재로 안 읽힌다.** 소유물이라는 값어치가 거기서 깨진다.

**2층 · 곁에 선 사람들 (무료)**
곁 하나를 누르면 그 사람과 나의 **방향** 한 줄만 나온다 — 생/극/동, 색, 언제 마지막으로 주고받았나.
숫자·점수·게이지 없음(인계서 §3 원칙 2).

**3층 · 사이 (유료 4,900원 = 지금의 궁합)**
2층에서 한 사람을 **펼치면** 열린다. `MatchDoc` 을 그대로 쓴다.

이 층 구분이 하는 일: 궁합이 *"메뉴에서 고르는 상품"* 에서
***"이미 곁에 있는 사람을 더 알고 싶어질 때 펼치는 것"*** 으로 바뀐다. 재구매 축(사람 수만큼)은 그대로다.

### 곁이 많아질 때 (시안 ⑤ vs ⑥에서 판정)

| 규칙 | 내용 |
|---|---|
| **입자 예산 고정** | 몇 명이 오든 곁이 쓰는 총량은 본체 입자의 16% 고정. 사람이 늘면 각자가 옅어진다. 성능도 인원과 무관 |
| **앞줄은 셋까지** | 최근 주고받은 셋만 궤도에 서고, 나머지는 바깥으로 물러나 배경 성운이 된다 |

두 번째가 더 중요하다. 열 명을 다 그리는 순간 그건 **친구 수 카운터**고,
숫자를 안 쓰기로 한 원칙이 그림으로 되살아난다. 셋으로 자르면 화면이 말하는 게
"몇 명 모았나"가 아니라 **"요즘 누가 곁에 있나"** 가 된다.

*상한 3은 잠정값이다.* 시안(`/gyeot-mock.html`) ⑥번 판에서 4~5도 견딜 만해 보인다 — 창업자 확정 대기.

## 5. 하지 말 것

- **판결 탭을 건드리는 것** — 이번 작업에서 판결 화면은 문구 하나도 안 바꾼다. 탭 껍데기만 씌운다
- **곁 탭 첫 화면을 결제벽으로 만드는 것** — 무료 유저가 열었을 때 살 것부터 보이면 빈 슬롯 금지 원칙과 같은 이유로 실패한다
- **개수 표기** — "곁 3", 배지 숫자, 진행바 전부 금지
- **하트·커플·핑크** — 인계서 §6. 곁은 연애 기능이 아니다
- **신규 캐릭터·마스코트** — 설계 헌장 명시 금지(2026-07-25)
- **상대 이름 받기** — 엔진이 의도적으로 안 받는다(인계서 §6). 곁 목록을 이유로 되살리지 마라
  → 곁의 표시 이름은 **유저가 스스로 붙이는 별칭**이거나 없다. 상대에게서 받는 값은 생년월일뿐이다

## 6. 순서 (이 순서를 지켜라)

| 단계 | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **1** | 하단 탭 껍데기 2개. 곁 탭엔 내 수호신(1층)만 | 가장 되돌리기 쉬운 변경. 다른 세션과의 충돌면도 여기가 제일 작다 |
| **2** | 곁 렌더 이식 — 시안 셰이더를 본체 입자 재배정으로 옮긴다 | 곁이 없는 곁 탭은 지금보다 나쁘다 |
| **3** | 곁 목록(2층) + 곁에 부르기 | 여기서 처음으로 **혼자가 아닌 화면**이 된다 |
| **4** | 궁합을 로비 버튼에서 3층으로 이동 | **마지막이다.** 궁합부터 옮기면 곁이 아직 없어서 탭에 상품 하나만 덩그러니 놓인다 |

**⚠️ 다른 세션과의 충돌**: 탭 도입은 이 리포에서 **가장 충돌면이 넓은 변경**이다(`App.jsx` 렌더 루트).
단계 1을 착수하기 전에 `origin/main` 을 받아 다른 세션 작업과 맞추고, 단계마다 쪼개서 올린다.
