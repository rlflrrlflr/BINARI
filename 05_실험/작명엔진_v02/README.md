## 교정된 원칙

**순서를 뒤집는다.** 성명학 조건에서 이름을 만들지 않는다 — **실제로 쓰이는 이름에서 출발해 한자를 맞춘다.**

**자르는 것과 표기하는 것을 분리한다** (`lib/filter.mjs`).
- **HARD(자름)** — 인명용 미등재 · 실사용 없음 · 가족 함자 겹침 · 형제와 근접음 · 성+합성어 · 두음 치환 단어 충돌 · 놀림 · 뜻 부적합 · 수리음양 순양순음
- **FLAG(표기만)** — 발음오행 · 81수리 사격 · 로마자 · 획수 유파

## 구성

```
data/fetch.mjs    공개 URL에서 원천 데이터 수집 (저장소엔 코드만, 데이터는 받아 씀)
lib/hanja.mjs     인명용 등재 · 원획/필획 · 부수 · 자원오행 · 훈음
lib/score.mjs     사격 · 수리음양 · 발음오행(2체계 병기) · 용신 적합
lib/filter.mjs    HARD / FLAG 경계 + 두음 치환 검사 + 뜻 적합성
lib/usage.mjs     실사용 통계 — 대법원 '선호하는 출생자 이름 현황'
```

```
node data/fetch.mjs      # 최초 1회
node demo.mjs            # 성·용신을 인자로 받는 예시
```

### 실사용 통계의 함정 두 가지

**⑴ `freqAccList`는 누적합이다.** 차분하지 않고 그대로 쓰면 모든 이름이 200만명대로 나와 순위·성비가 통째로 무의미해진다. `lib/usage.mjs`가 차분을 담당한다.

**⑵ 집계 기간이 2008–2019다.** 통계 사이트(namechart·baby-name 등)는 2025년까지 집계하므로 **같은 이름도 수치가 다르다.** 실측 대조:

| 이름 | 대법원 원본(2008–2019) | 통계 사이트(~2025) | 차이 |
|---|---|---|---|
| 태윤 | 8,712 | 11,539 | 최근 6년치만큼 |
| 태오 | 1,911 | 5,895 | **3배** — 최근 급상승 이름 |
| 리오 | 360 | 547 | 상승 |
| 태린 | 208 (남 5%) | 253 | 성비 판정은 일치 |

**즉 이 데이터는 "지금 얼마나 쓰이나"가 아니라 "누적으로 얼마나 쌓였나"다.** 최근 3년 추세는 여전히 못 본다 — 신흥 이름은 과소평가된다. 추세가 필요하면 별도 소스가 필요하다.

## 제품에 넣을 때 (창업자 지시 2026-08-10)

- **리포트에 로직을 노출하지 않는다.** 사격 수치·발음오행 체계명·필터 이름 같은 계산 과정은 유저 화면에 쓰지 않는다. 그 자리에는 **그래프로 보여줄 수 있는 것**을 넣는다(예: 오행 분포, 후보가 좁혀지는 과정, 실사용 추이).
- **이름을 제안할 때는 한자를 반드시 함께 표기한다.** 한글 이름만 단독으로 내보내지 않는다.
- 이 두 가지는 `../../01_기획전략/비나리_기획전략_작명기능구상_v01.md` §3 의 리포트 설계에 반영한다.
