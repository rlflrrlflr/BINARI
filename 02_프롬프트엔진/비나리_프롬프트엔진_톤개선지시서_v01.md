## 0. 이 작업의 목적 한 줄

**판결의 화자에게서 "신앙 고백 요구"를 제거한다 — 단, 판돈이 작은 질문에서만.** 캐릭터를 만들거나 비주얼을 바꾸는 작업이 아니다.

## 1. 왜 하는가 (근거 — 이 전제가 흔들리면 작업을 멈추고 다시 물어라)

- 한국 20대의 점·사주 **신뢰율은 27%**(전 연령 최저, 60대+ 46%)인데 **AI 운세 경험률은 46%**다(한국갤럽 2026-03). 즉 **믿지 않으면서 소비한다.** "전지전능한 수호신"을 전제로 깔면 73%에게 문이 닫힌다.
- 반대로 **심드렁함을 전면에 깔면 안 되는 근거**도 있다. 이용 동기 1위는 재미(28%)가 아니라 **불안 해소 54.2%**(엠브레인)이고, 냉소·비꼬는 유머는 정서조절에 효과가 없거나 역효과이며(Samson & Gross 2012), 고심각도 맥락의 유머는 지각 위험·행동의도를 떨어뜨린다(McGraw 외 2012, 5연구).
- 반면 **고강도 부정 정서에서는 거리두기가 효과적**이다(Sheppes 외 2011 / Kross 자기거리두기 계열).
- → **갈리는 변수는 톤이 아니라 판돈(stakes)이다.** 점심 메뉴엔 심드렁이 맞고, 이직·이별엔 심드렁이 무례로 착지한다.
- **톤과 확신도는 분리 가능하다.** 바넘 효과 수용은 '경건함'이 아니라 단언 강도·관련성·권위에서 온다(Dickson & Kelly 1985, 약 50개 연구 리뷰). 단 '자신감 있는 전달'은 이득이지만 **'거짓 확신'은 이득이 없다**(Gaertig & Simmons 2018, 11연구 N=4,806).
- → **목표 화법: "몰라, 알아서 해"가 아니라 "그거 하지 마. 별로야."** 심드렁하면서 단언한다.

## 2. 절대 하지 말 것 (설계 헌장 + 톤 판정 금지선)

1. **신규 캐릭터 제작 금지** — 고양이 등. 심드렁 캐릭터를 앱 페르소나로 전환해 리텐션을 개선한 정량 사례는 0건이고, 국내 직접 선례는 역방향이다(캐릭터 챗봇 헬로우봇 MAU 9만 vs 무캐릭터 점신 95만, 모바일인덱스 2025-02).
2. **수호신 비주얼(GPU 파티클) 교체·수정 금지** — ChatGPT가 복제 못 하는 유일 자산이다. 캐릭터로 바꾸면 astello가 앞선 판(정적 마스코트)으로 들어간다.
3. **정령 시각 요소 부활 금지** — 리포는 이미 두 번 왕복했다(v24 혈액형 마스코트 잔재 제거 → v27 정령 위성 제거 → v41 정령 세계관 편입, v68 위스프 제거). 세 번째 왕복 비용은 개발 라인 1개가 진다.
4. **판결문 형식 보존** — 축·카드 수를 늘리지 않는다. JSON 스키마 필드를 추가·삭제하지 않는다.
5. **모를 권리** — 묻지 않은 영역의 예언·경고를 먼저 꺼내지 않는다. 톤이 가벼워져도 이 규칙은 그대로다.
6. **가드레일 톤은 절대 건드리지 않는다** — 자해 암시·타인 가해·투자/의료/법률. 여기서 심드렁은 재앙이다. 현행 유지.
7. **A형(큰 결정)·B형(감정 충동) 톤 변경 금지** — 이번 작업 범위는 C형/속결뿐이다.

## 3. 코드 사실 — 착수 전 반드시 읽을 것

작업 전 이 4개를 직접 확인하고 시작하라. **특히 (3)·(4)는 내가 확인 중 발견한 함정이다.**

**(1) SYS 프롬프트 위치**
`app/src/App.jsx:1568` — `const SYS = \`...\`;` 단일 템플릿 리터럴. 관련 절: `## 존재의 전제`, `## 질문 분류`(A/B/C), `## 층위·가중치`(여기 정령 정의가 들어있음), `## 3화법`(단호|격려|충고), `## 규칙`, `## 가드레일`, `## 출력`.

**(2) 정령의 현재 정의** (SYS `## 층위·가중치` 절 말미)
> 정령: 수호신을 복원할 때 조각 하나가 달빛에 물들어 돌아가지 않고 곁에 남은 것 — 유저의 달 별자리 기운을 띤 장난꾸러기. **판결 미반영, funLine 재미 한마디 전용.** 능청·너스레·짓궂은 농담 환영.

**(3) ⚠️ 함정 1 — `quick` 플래그는 모델에 전달되지 않는다**
`judge(hi, quick = false)` (`App.jsx:1967`). `quick`은 딱 두 곳에만 쓰인다:
- 계측 태그: `mode: quick ? "quick" : "ritual"`
- **콜2 생략**: `if (quick) { setDetail({ _quick: true }); }` (`App.jsx:2007`) — v16 B5 결정, 원가 절반

**SYS와 userText는 두 모드가 완전히 동일하다.** 모델은 질문 문장만 보고 category A/B/C를 스스로 판정한다. 따라서 "속결 프롬프트만 고친다"는 표현은 부정확하다 — **모드를 프롬프트로 전달하는 배선이 먼저 필요하다.**

**(4) ⚠️ 함정 2 — 속결에는 subline도 정령 funLine도 없다**
- 콜1 출력 스키마(`concludeMsg`, `App.jsx:1993`): `category / tone / direction / verdict / against / total` — **subline·funLine 없음**
- 콜2 출력 스키마(`explainMsg`, `App.jsx:1895`): `subline / reasons / funLine / disclaimer`
- 속결은 콜2를 건너뛰므로 **속결 화면에 존재하는 텍스트는 `verdict` 한 줄(45자 이내)과 `tone` 필드뿐이다.**

→ **따라서 "속결 = 정령이 심드렁하게"는 구현 불가다.** 정령을 속결에 등장시키려면 콜2를 켜야 하고 그건 원가 2배 + v16 B5 결정 되돌리기다. **기각.**
→ **구현 가능한 형태: 속결에서 수호신 자신이 심드렁하게 한 줄로 단언한다.** 화자를 바꾸는 게 아니라 같은 화자의 화법을 판돈에 맞게 가른다. §1의 "톤과 확신도는 분리 가능"이 정확히 이걸 뒷받침한다.

## 4. 해야 할 일

### 4-1. 모드를 프롬프트에 전달 (배선)

`quick` 플래그를 콜1 유저 턴에 실어라. **SYS 본문에 조건 분기를 넣지 말고**, 유저 턴에 한 줄 태그로 붙이는 방식을 권한다 — 이유: SYS는 프롬프트 캐싱 영역이고(v14 결정) 평가 하네스가 SYS를 그대로 추출해 쓰므로(§5 참조), SYS를 모드별로 갈래 치면 캐시 효율과 하네스 정합이 함께 깨진다.

권장 형태(문구는 조정 가능):
```
userText 뒤에 붙임 — 속결일 때만
[판돈] 낮음 — 유저가 '속결'로 물었다. 가볍게 툭 답한다.
```
그리고 SYS `## 3화법` 또는 `## 규칙`에 이 태그를 해석하는 규칙 1~2줄을 추가한다.

### 4-2. 속결 화법 규칙 작성 (핵심 작업)

SYS에 추가할 규칙의 요건:

| 지켜야 할 것 | 하지 말 것 |
|---|---|
| **단언은 유지** — 방향을 분명히 찍는다 | "몰라 / 알아서 해 / 네 마음대로" 류 위임·회피 |
| 짧고 툭 던지는 어조, 과장된 경건함 제거 | **냉소·비꼼·유저 조롱** (정서조절 역효과 근거) |
| 지표 정박은 그대로 — 근거는 여전히 지표 | 유저의 고민을 사소하게 취급하는 말("그게 고민이야?") |
| 기존 `## 규칙`의 구체값 지시 유지(메뉴명 콕 찍기·시각·날짜) | 전문 용어 노출(기존 층위 분리 규칙 그대로) |

방향 예시(그대로 쓰지 말고 톤 감만 참고 — 실제 문구는 실모델 출력을 보며 조율):
- (현행 경건) "물이 겹겹인 때야. 오늘은 발을 담그지 마."
- (속결 심드렁) "짬뽕. 오늘 네 불기운엔 그게 맞아."
- (속결 심드렁) "보내지 마. 그거 지금 마음 아니라 새벽이야."

**tone 필드 처리**: 현행 `단호|격려|충고` 3화법을 건드리지 않는 게 안전하다. 속결은 대부분 `단호`로 떨어질 것이므로 별도 값 추가 없이 화법 규칙만으로 처리하고, 정말 필요하면 4번째 값 추가를 **먼저 물어라**(스키마 변경 = 판결문 형식 영역).

### 4-3. 의식(ritual) 모드는 손대지 않는다

현행 무게·의례 톤 그대로. 근거: 고심각도 맥락에서 유머는 지각 위험·행동의도를 낮춘다(McGraw 2012). 의식을 청한 유저는 스스로 판돈이 크다고 선언한 것이다.

## 5. 검증 방법 — 눈으로 보고 판단할 것

**이 작업은 테스트 통과로 끝나지 않는다. 실모델 출력을 사람이 읽어야 한다.**

**(1) 평가 하네스가 이미 이 작업에 맞게 준비돼 있다** — `app/eval/`
- `run-eval.mjs`가 **`App.jsx`에서 SYS를 직접 추출**한다(`App.jsx`의 `const SYS = \`` ~ `` `; `` 구간, 마커 `"층위 분리"` 검사). 드리프트가 자동 방지된다.
- `questions.json`(20문항)에 이미 **`mode: "quick" | "ritual"` 필드가 있고**, CSV 출력에 `mode` 컬럼이 포함된다 → **모드별 톤 비교가 바로 된다.**
- `personas.json` 5인 × 20문항. 실행: `ANTHROPIC_API_KEY=sk-... node eval/run-eval.mjs` (`--full`로 근거까지)
- `build-scorer.mjs` → `scorer.html` 블라인드 채점 페이지(페르소나·자동플래그 숨김).

**⚠️ 하네스 정합 주의**: SYS는 자동 추출되지만 **§4-1에서 유저 턴에 붙이는 모드 태그는 하네스가 모른다.** `run-eval.mjs`의 메시지 구성부(`system(p)` / content 조립)에도 **같은 방식으로 태그를 추가**하라. 안 하면 하네스가 앱과 다른 것을 재게 된다.

**(2) 판정 기준 — 3개를 사람이 읽고 확인**
1. **속결 verdict가 단언을 유지하는가** — 방향이 모호해진 출력이 하나라도 있으면 규칙 실패.
2. **냉소로 착지하지 않았는가** — 유저를 깎는 문장, 고민을 사소하게 취급하는 문장 0건이어야 한다.
3. **의식 모드 출력이 변하지 않았는가** — 변경 전/후 동일 질문 대조. 변했으면 배선이 새고 있다.

**(3) 회귀 테스트** (전부 통과해야 함)
```
npm run build
npm run preview   # 별도 셸
node e2e/smoke.mjs        # 현재 26/26
node e2e/verdict.mjs      # 판결 구조 검사
node e2e/v29-check.mjs
node e2e/webgl-check.mjs
```
`mansae-test.mjs`는 이 작업과 무관하나 돌려서 손상 없음을 확인하면 좋다.

**(4) 가드레일 회귀** — 하네스 질문 세트의 가드레일 문항(자해 암시 등)에서 **톤이 절대 가벼워지지 않았는지** 반드시 눈으로 확인. 여기서 실패하면 즉시 롤백.

## 6. 이 작업이 실측으로 판정되는 방식 (참고 — 구현 범위 아님)

톤이 옳았는지는 코드가 아니라 광고·리텐션 데이터가 판정한다. 6주 G0-b 기간에:
- 소재 12개 중 B(단언)·C(GPT 반사) 6개를 **신비 3 : 심드렁 3**으로 재배분
- 앱 내에서는 `question_asked`·`verdict_shown`에 **이미 `mode` 속성이 실려 있어** 신규 이벤트 없이 코호트 분해 가능
- 판정: ①소재 톤별 완주율 ②모드별 D7 ③속결 비중 변화. 광고 CTR만으로 판정하지 않는다(클릭은 호기심)
- **코어 톤 확대 조건**: 심드렁 소재 완주율이 신비 대비 **+20% 이상** 그리고 속결 D7 ≥ 의식 D7. 그 전까지 의식·A형 톤은 건드리지 않는다

## 7. 작업 후 기록 (프로젝트 규칙)

- `작업로그.md`에 서술 기록 — 요청·판단·구현·검증 결과(하네스 CSV에서 인상적인 출력 몇 개를 그대로 인용하면 좋다)

- 브랜치에 커밋·푸시. **`main` 푸시는 사용자의 명시 지시가 있을 때만**(main = Vercel 자동배포).

## 8. 막히면 물어볼 것 (혼자 결정하지 말 것)

1. **JSON 스키마 변경이 필요해진 경우**(tone에 4번째 값 추가 등) — 판결문 형식 영역이므로 먼저 물어라.
2. **속결에서 정령을 살리고 싶어진 경우** — 콜2를 켜야 하므로 원가 2배. §3(4)에서 기각된 안이다.
3. **의식 톤도 손봐야 한다고 판단되는 경우** — 이번 범위 밖. 근거를 정리해 제시하고 승인받아라.
4. **실모델 출력에서 심드렁이 계속 냉소로 착지하는 경우** — 규칙을 더 조이기 전에 보고하라. "심드렁 자체가 이 제품과 안 맞는다"는 결론일 수 있고, 그건 전략 판정을 되돌리는 사안이다.
