## 1. 실측 — 루프는 이미 돌고 있고, 막힌 데가 정해져 있다

45일 · `is_internal` 제외:

| 단계 | 값 |
|---|---|
| 판결 노출 `verdict_shown` | 101회 / 14명 |
| **공유 발신** `verdict_shared` | **5건 / 2명** |
| 공유 유입 `shared_verdict_view` | 5회 / 4명 |
| 유입 후 CTA `shared_cta` | 4회 / 3명 |
| first-touch=`share` 의 완주 | opens 7 → 온보딩 3 → **생일 제출 2 → 질문 2** |

**해석**: 공유는 판결 100번에 5번(5%)인데, 일어나면 **유입 5명 중 2명이 수호신까지 만든다(40%)**.
병목은 수신이 아니라 **발신**이다. 게다가 공유 버튼은 이미 판결 카드 최상단 금색 CTA다 —
**위치 문제가 아니라 보낼 이유·보낼 물건의 문제**다.

거친 k 추정: 완주 2명 / 활성 14명 ≈ **0.14**. 분모(유저)가 아니라 **분자(공유 건수)** 를 키워야 하는 국면.

## 2. 정책 판단 — 결과 공개 범위 (창업자 결정 2026-08-15)

> "결과를 오픈해도 상관없을 것 같다. 귀인지도도 다 오픈되는데 그냥 하더라. 아니면 오픈 가능한 정보를 선별하든가."

**채택**: 결과 공개를 원칙적으로 허용한다. 단 **선별한다.**
선별 기준은 취향이 아니라 **역산 가능성**이다 — 아래가 이 문서의 가장 중요한 발견이다.

### ⚠️ 아홉 하늘 값은 몇 개만 모여도 생년월일이 복원된다

각 값은 서로 다른 주기의 나머지(remainder)다. 중국인의 나머지 정리 그대로, **주기가 서로 소일수록 조합의 유일성이 급격히 올라간다.**

| 값 | 주기 |
|---|---|
| 마야 촐킨(톤×날) | 260일 |
| 자바 웨톤(요일×파사란) | 35일 |
| 나크샤트라 | 27분할(달 위치) |
| 달 위상 | 약 29.5일 |
| 아칸 요일이름 | 7일 |
| 일본 혼메이세이 | 9년 |
| 납음(년 갑자) | 60년 |

- **촐킨 × 웨톤**만으로 LCM 1,820일 ≈ **약 5년 창에서 유일**하다. 나이대만 알면 생일이 좁혀진다.
- 여기에 **납음·혼메이세이**(연 주기)가 더해지면 **연도까지 특정**된다.
- 즉 "아홉 이름을 한 장에 다 싣는다"는 **생년월일을 공개하는 것과 실질적으로 같다.**

**따라서 정책**: 공개용 이미지 한 장에 실을 수 있는 파생 이름은 **최대 2개, 주기가 겹치는 조합은 금지**(촐킨+웨톤 동시 노출 불가). 가장 안전한 형태는 **한 장에 하나**다.
→ 시각 설계에서 "아홉 개를 한 장에 나열"하는 안은 이 이유로 기각한다.

*(이 판단은 계산 근거가 명확하지만, 실제 위험 크기는 표본·맥락에 따라 다르다. 법무 검토 대상이 아니라 **설계 기본값**으로 둔다 — 기본을 안전하게 두고, 열고 싶으면 그때 판단한다.)*

## 3. 궁합 종속성 해제

앞선 권고(궁합 초대 루프)는 **철회하지 않되 1순위에서 내린다.** 창업자 지적이 맞다 — 우리는 사주 한 축이 아니다.

| 루프 후보 | 완결에 필요한 사람 | 마찰 | 우리만 가능? |
|---|---|---|---|
| 궁합 초대 | **2명** | 상대 생일 요청 + 관계 노출 | 아니오(8개 중 5개사 보유) |
| 판결 자랑(부적·공유) | 1명 | 사적 고민 노출 · 맥락 필요 | 부분(판결 포맷) |
| **파생 이름 한 장** | **1명** | 거의 없음(내 것만 나감) | **예 — 9엔진 보유는 우리뿐** |
| 수호신 초상(소지품) | 1명 | 없음(자랑이 아니라 소지) | 예 |

**로직상 결론**: 루프의 1차 단위는 **1인 완결형**이어야 한다. 2인 완결형(궁합)은 1인 루프가 돌기 시작한 뒤 **2차 증폭**으로 붙인다.

## 4. 판별 기준 (미리 정한다)

| 관측 | 뜻 |
|---|---|
| 새 공유 단위 도입 후 `verdict_shared + 신규 카드 공유` / `verdict_shown` 이 **15% 미만** | 발신 마찰이 물건 문제가 아니었다 → 루프 대신 광고 소재로 |
| 공유 1건당 유입이 **1.0 미만** | 받는 쪽 훅이 약하다 → 랜딩·OG 문제 |
| 유입→생일 제출이 **40% 아래로 하락** | 온보딩 길이가 병목(현재 share 유입 2/5) |

**신설 필요 계측**: `card_saved`(카드 저장·공유 실행), `card_kind`(어떤 이름/단위였나), OG 노출 경로 구분.
