# 저장소 규칙 인계서 — 비개발자가 AI와 함께 굴리는 리포를 어떻게 짤 것인가

2026-08-02 작성. **다른 계정·다른 프로젝트에 그대로 옮겨 쓰기 위한 문서.**
비나리 리포에서 실제로 굴러간 규칙만 담았고, **죽은 규칙은 죽었다고 적었다**(§7).

---

## 0. 이 리포가 남과 다른 전제

일반적인 개발 리포는 **개발자 여럿이 코드 하나**를 만진다.
이 리포는 정반대다.

| | 보통의 리포 | 이 리포 |
|---|---|---|
| 사람 | 개발자 여러 명 | **비개발자 1명 + AI 세션 여러 개** |
| 기억 | 사람이 맥락을 기억 | **AI는 매번 기억을 잃는다** |
| 내용물 | 코드 | **문서(기획·전략·리서치) + 코드** |
| 병렬 | 사람이 나눠 맡음 | 세션 여러 개가 **동시에** 같은 리포를 만짐 |

**여기서 모든 규칙이 나온다.** 폴더를 예쁘게 나누는 게 목적이 아니라,
**기억을 잃는 협업자에게 매번 같은 맥락을 자동으로 넘기는 것**이 목적이다.

> 이 문서에서 가장 중요한 건 폴더 번호가 아니라 **§3(로그 3종 분리)과 §4(CLAUDE.md)** 다.
> 시간이 없으면 그 둘만 가져가도 된다.

## 1. 큰 그림 — 한 리포 안에 성격이 다른 두 구역

```
{프로젝트}/
├─ CLAUDE.md          ← AI가 매 세션 자동으로 읽는 상시 컨텍스트  ★핵심
├─ README.md          ← 사람이 처음 보는 문 + 폴더·파일명 규칙
├─ 변경이력.md         ← 무엇을 바꿨나 (한 줄 대장)
├─ 전략로그.md         ← 전략에서 왜 그렇게 판단했나
├─ 작업로그.md         ← 개발에서 왜 그렇게 판단했나
│
├─ 01_기획전략/        ┐
├─ 02_프롬프트엔진/     │ 문서 구역 — 파일명 규칙 엄격 적용
├─ 03_비주얼프로토타입/  │ (버전이 붙는 '산출물'들)
├─ 04_리서치/          │
├─ 09_구버전/          ┘
│
├─ app/               ← 코드 구역 — 파일명 규칙 적용 안 함(§2-3)
└─ .claude/skills/    ← AI에게 시킬 한 단어 명령 (§6)
```

**핵심은 이 두 구역의 규칙이 다르다는 것이다.** 문서는 버전이 찍힌 산출물이고,
코드는 계속 살아 움직이는 유기체다. 같은 규칙을 씌우면 둘 중 하나가 망가진다.

## 2. 폴더 규칙

### 2-1. 번호를 붙이는 이유

`01_`, `02_` … 숫자 접두어는 **정렬 순서를 내가 정하기 위한 것**이다.
숫자가 없으면 파일 탐색기가 가나다순으로 늘어놓아서, 중요한 폴더가 아래로 밀린다.

번호는 **작업 흐름 순서**로 매긴다. 비나리 기준:

| 폴더 | 담는 것 |
|---|---|
| `01_기획전략/` | 왜 만드는가 · 무엇을 할 것인가 · 인계서 · 의사결정 문서 |
| `02_프롬프트엔진/` | 프롬프트 설계·지시서 (AI 제품이면 별도 구역이 필요하다) |
| `03_비주얼프로토타입/` | 화면 시안·프로토타입 (코드 포함 가능) |
| `04_리서치/` | 시장·경쟁사·유저 조사, 외부에서 받은 자료 |
| `09_구버전/` | 옛 버전 보관 — **실제로는 거의 안 쓰게 된다(§7)** |

**새 프로젝트에선 이름을 바꿔 쓴다.** 예: 광고 캠페인이면
`01_전략/ 02_크리에이티브/ 03_매체/ 04_리서치/ 09_구버전/`.

**규칙은 셋뿐이다.**
1. 두 자리 숫자 + 언더바 + 한글 이름
2. **09는 항상 구버전 자리로 비워둔다** (중간에 폴더가 늘어도 맨 끝 유지)
3. 폴더는 처음에 4~5개로 시작한다. 늘리기는 쉽고 줄이기는 어렵다

### 2-2. 폴더마다 README.md를 하나씩 둔다

각 폴더에 **그 폴더의 규칙만 적은 짧은 README**를 둔다. 3~5줄이면 충분하다.

```markdown
# 01_기획전략

사업/서비스 기획, 전략, 로드맵 등 **기획 산출물**을 보관합니다.

## 파일명 규칙
{프로젝트}_기획전략_{산출물}_vNN.ext

> 새 버전을 올리면 직전 버전은 `../09_구버전/`으로 옮기고,
> 변경 내용을 루트 `변경이력.md`에 기록합니다.
```

이유: **AI 세션이 그 폴더에 파일을 만들 때 이 README를 읽고 규칙을 따른다.**
사람을 위한 게 아니라 AI를 위한 안내판이다. 실제로 비나리에서
번호 폴더 안 문서 **17개 전부 규칙을 지켰다(위반 0건)**.

### 2-3. 코드 폴더(`app/`)는 이 규칙에서 제외한다

`app/` 안은 그냥 그 기술의 표준 관례를 따른다(`src/`, `api/`, `public/`, `README.md`, `ROADMAP.md`).
문서 파일명 규칙을 코드에 씌우려 하지 마라 — 도구들이 관례 이름을 기대한다.

비나리 `app/` 안의 문서는 이렇게 굴러간다(참고용):

| 파일 | 성격 |
|---|---|
| `README.md` | 이 코드를 어떻게 돌리나 |
| `ROADMAP.md` | 개발 진행 체크리스트 |
| `유지보수_규칙.md` | 사고 이력과 방어 장치 |
| `AUDIT-2026-07-23.md` | 날짜가 곧 정체성인 1회성 문서 → `{종류}-{날짜}.md` |
| `작업지시_{주제}_{날짜}.md` | 다른 세션에 넘길 작업 지시서 |

## 3. 로그 3종 분리 — 이 리포에서 가장 값어치 있는 규칙 ★

세 파일이 **각각 다른 질문에 답한다.** 하나로 합치면 전부 쓸모없어진다.

| 파일 | 답하는 질문 | 형식 | 쌓는 방향 |
|---|---|---|---|
| `변경이력.md` | **무엇을** 바꿨나 | 표 한 줄 (날짜·버전·무엇·왜) | 최신이 **위** |
| `전략로그.md` | **전략**에서 왜 그렇게 판단했나 | 서술 (요청·근거·**기각한 선택지**·결론) | 최신이 **아래** |
| `작업로그.md` | **개발**에서 왜 그렇게 판단했나 | 서술 | 최신이 **아래** |

### 왜 나누는가

- **변경이력**은 훑어보는 대장이다. 표라서 스캔이 된다. 여기에 서술을 쓰면 대장이 아니게 된다.
- **전략로그·작업로그**는 *경위*다. 결론만 필요하면 정본 문서를 보면 된다.
  이 로그의 존재 이유는 **기각한 선택지와 그 이유**를 남기는 것이다.

### 기각 기록이 왜 중요한가 — 실제 사례

비나리에서 같은 요소가 **v24 제거 → v41 편입 → v68 제거**로 세 번 오갔다.
왜 뺐는지가 안 적혀 있어서, 다음 세션이 "이거 있으면 좋겠는데?" 하고 되살린 것이다.
**AI는 지난 대화를 기억하지 못한다.** 이유를 안 적으면 같은 논쟁을 무한 반복한다.

### 로그 작성 규칙

```
- 중요한 판단이 나올 때마다 즉시 기록한다. 세션 끝에 몰아 쓰지 않는다.
- 결론이 바뀌면 로그만 쌓지 말고 정본 문서와 CLAUDE.md의 표를 함께 고친다.
- 형식: 요청 · 판단 근거 · 기각된 선택지 · 결론
```

## 4. `CLAUDE.md` — AI가 매 세션 자동으로 읽는 파일 ★

리포 루트에 두면 **모든 AI 세션이 시작할 때 자동으로 읽는다.** 이게 "기억 이식" 장치다.

### 담을 것 (비나리 실제 구성)

1. **제품 한 문단** — 뭘 만드는지, 지금 어디 배포돼 있는지
2. **팀 구성과 그 함의** — 인원뿐 아니라 *"그래서 무엇이 제약인가"*
   (예: "개발자가 없다 → 개발은 병렬화되지 않는다")
3. **문서 지도** — *"어떤 물음의 정본이 어느 파일인가"* 표. 가장 자주 쓰인다
4. **기록 규칙** — 세션이 지켜야 할 로그 작성 규칙
5. **현재 상태 표** — 지금 무엇이 검증됐고 무엇이 미검증인지
6. **응답 규칙** — 나에게 어떻게 말할지 (예: "주장만 하지 말고 근거도")
7. **설계 헌장** — *어기려면 먼저 물어야 하는* 불변 제약
8. **운영 규칙** — 배포·브랜치·파일명

### 지킬 것

- **짧게 유지한다.** 상세는 정본 문서로 링크만 건다. 길어지면 AI가 흘려 읽는다.
- **§7 설계 헌장이 핵심이다.** "이건 하지 마라"를 적어두지 않으면
  AI는 좋아 보이는 개선을 계속 제안하고, 매번 같은 걸 거절하느라 시간이 녹는다.
- 결론이 바뀌면 로그와 **함께** 고친다.

> **문서 지도 형식** (그대로 베껴 쓸 것)
>
> | 물음 | 정본 |
> |---|---|
> | 왜 존재하는가 | `01_기획전략/{프로젝트}_기획전략_비전_v01.md` |
> | 지금 무엇을 할 것인가 | `01_기획전략/{프로젝트}_기획전략_실행계획_v01.md` |
> | 무엇을 바꿨나 | `변경이력.md` |

## 5. 파일명 규칙

```
{프로젝트}_{영역}_{산출물}_vNN.ext
```

예: `비나리_기획전략_개발인계서_v15.md` · `비나리_리서치_경쟁8사가격포지셔닝_v01.pdf`

| 조각 | 규칙 |
|---|---|
| `{프로젝트}` | 리포 전체에 하나. 한글 프로젝트명 |
| `{영역}` | **폴더 이름과 일치시킨다** (`01_기획전략` → `기획전략`) |
| `{산출물}` | 문서의 구체적 이름. 공백 없이 붙여 쓴다 |
| `vNN` | **항상 맨 뒤**, 확장자 바로 앞. 두 자리(`v01`) |

### 왜 버전이 맨 뒤인가

파일명이 가나다순으로 정렬될 때 **같은 산출물의 버전들이 자동으로 붙어서 나열된다.**
앞이나 중간에 두면 흩어진다. 이게 유일한 이유이자 충분한 이유다.

### 왜 영역명을 파일명에 또 넣는가 (폴더에 이미 있는데)

**파일을 폴더 밖으로 꺼낼 일이 많기 때문이다** — 카톡으로 보내고, 메일에 붙이고,
AI 채팅창에 업로드한다. 그 순간 폴더 맥락은 사라진다.
`v01.md`만 남으면 아무도 그게 뭔지 모르지만,
`비나리_리서치_경쟁8사가격포지셔닝_v01.pdf`는 파일명만으로 완결된다.

### 버전 축은 둘로 나뉜다

- **문서 버전** `v01, v02…` — 문서마다 독립. 그 문서를 고칠 때만 올린다
- **앱 버전** `v106` — 코드 전체가 공유하는 하나의 축. 화면 배지에 노출

**둘을 맞추려 하지 마라.** 비나리는 문서가 `v01`인데 앱은 `v106`이다. 정상이다.

## 6. AI에게 시키는 규칙 (`.claude/`)

### 6-1. 한 단어 명령 만들기 — `.claude/skills/{이름}/SKILL.md`

자주 시키는 일은 스킬로 박아두면 **단어 하나로** 부를 수 있고,
**새 세션도 그 규칙을 안다.**

```markdown
---
name: 검진
description: 앱 건강검진. 사용자가 "검진", "점검", "배포해도 돼?" 라고 하면 실행한다.
---

# 검진

## 실행
cd app && node health-check.mjs

## 보고 방식
- 사용자가 결정할 수 있는 형태로 줄여 말한다: ①배포해도 되는가 ②뭘 고쳐야 하는가
- ✗가 하나라도 있으면 배포하지 않는다

## 하지 말 것
- 검진 결과를 근거로 main에 밀지 마라. main 푸시는 명시 지시가 있을 때만.
```

**요령**: 명령어를 외우게 만들지 마라. 도구가 "터미널을 하나 더 열어라"를 요구하는 순간
비개발자에게는 없는 도구다. 스크립트가 준비물을 스스로 갖추게 만든다.

### 6-2. 브랜치·커밋·배포

| 항목 | 규칙 |
|---|---|
| 브랜치 | `claude/{주제-슬러그}-{임의문자}` — Claude Code가 자동 생성. 그대로 쓴다 |
| 작업 위치 | **항상 피처 브랜치.** `main`에 직접 커밋하지 않는다 |
| main 푸시 | **내가 "배포"라고 말했을 때만.** main 푸시 = 자동배포이기 때문 |
| PR | 요청했을 때만 만든다 |

**커밋 메시지 형식** (한글, 제목은 `무엇 — 왜`):

```
v106 · 셈 — 카드가 자기 판결을 반박하던 표시 버그 + 손질 4건

실기기 스샷 3장 전부 "N개 중 1개 찬성"이었다. (…무엇이 문제였는지…)

- 표시 수를 판결을 민 표로 교정
- 검진에 재발 검사 2종 추가

검진 0심각 / smoke 25 / verdict 29 — 전부 PASS.
```

제목은 **증상이나 결과**를 쓰고, 본문에 **왜**와 **검증 결과**를 남긴다.
"fix bug" 류는 6개월 뒤의 나에게 아무 정보도 주지 않는다.

### 6-3. 병렬 세션 규칙 (여러 창을 동시에 쓸 때)

비나리는 세션 6개가 동시에 같은 리포를 만졌다. 그때 필요한 것:

- **다른 세션이 만든 문서를 내가 다시 만들지 않는다.**
  파일을 만들기 전에 원격 브랜치 전체를 확인한다 — 실제로 같은 경로에 중복 문서를 만들어 충돌한 적이 있다
- **병합이 깨끗한 것과 결과가 성한 것은 다른 문제다.** 병합 후 반드시 테스트를 다시 돌린다
  (실제 사고: 충돌 0건으로 병합됐는데 세션 간 *암묵적 전제*가 어긋나 테스트가 무력화됐다)
- 푸시 전 항상 `git fetch` — main이 그 사이 움직였을 가능성이 높다

## 7. 실제로는 죽은 규칙 (정직하게 기록)

**`09_구버전/`으로 옮기는 규칙은 사실상 폐기됐다.** 마지막 사용이 2026-07-20이다.

이유: **git이 이미 모든 옛 버전을 갖고 있다.** 파일을 손으로 옮기는 건
중복 보관이고, 리포만 무거워진다.

**그래도 폴더는 남겨두는 게 낫다.** 쓸모가 있는 경우가 둘 있다:
- **git을 안 쓰는 사람과 폴더째 주고받을 때** (팀원에게 압축파일로 전달)
- **PDF·PPT처럼 git이 차이를 못 보여주는 파일**의 옛 버전

> **새 프로젝트 판단**: 팀이 git에 익숙하지 않거나 문서를 압축파일로 주고받으면 `09_`를 살려 쓰고,
> 전부 git으로 굴리면 폴더만 만들어 두고 신경 끄면 된다.

## 8. 새 프로젝트 셋업 (그대로 복사)

### 8-1. 폴더 만들기

```bash
mkdir -p 01_전략 02_크리에이티브 03_시안 04_리서치 09_구버전
touch CLAUDE.md README.md 변경이력.md 전략로그.md 작업로그.md
```

### 8-2. AI에게 그대로 줄 지시문

> 이 리포는 **비개발자 1명 + AI 세션 여러 개**가 함께 굴린다. 아래 규칙을 지켜라.
>
> **파일명**: `{프로젝트}_{영역}_{산출물}_vNN.ext` — 버전은 항상 맨 뒤, 두 자리.
> `{영역}`은 폴더 이름과 일치시킨다. 코드 폴더(`app/` 등)는 이 규칙에서 제외하고 그 기술의 관례를 따른다.
>
> **기록**: 모든 변경은 `변경이력.md`에 한 줄(날짜·버전·무엇·왜, 최신이 맨 위).
> 전략 판단은 `전략로그.md`, 개발 판단은 `작업로그.md`에 **기각한 선택지와 그 이유까지** 남긴다(최신이 맨 아래).
> 중요한 판단이 나올 때마다 즉시 쓴다 — 세션 끝에 몰아 쓰지 않는다.
>
> **정본**: 결론이 바뀌면 로그만 쌓지 말고 `CLAUDE.md`의 상태 표와 해당 정본 문서를 **함께** 고친다.
>
> **브랜치**: 작업은 피처 브랜치에서. `main` 푸시는 내가 "배포"라고 말했을 때만. PR은 요청했을 때만.
>
> **커밋 메시지**: 한글. 제목은 `무엇 — 왜`, 본문에 이유와 검증 결과.
>
> **새 파일 만들기 전**: 원격 브랜치 전체를 확인해서 다른 세션이 이미 만들지 않았는지 본다.
>
> **응답**: 판단·권고에는 근거를 붙인다(리포 내 사실·실측 수치·출처 있는 자료).
> 근거가 없으면 "근거 없음/추정"이라고 표시한다. 추론과 사실을 섞지 않는다.

### 8-3. 첫 주에 채울 것

| 순서 | 할 일 | 왜 먼저인가 |
|---|---|---|
| 1 | `CLAUDE.md`의 **문서 지도**와 **설계 헌장** | 이 둘이 없으면 AI가 매번 다른 답을 한다 |
| 2 | 폴더별 `README.md` (3~5줄) | AI가 파일을 만들 때 읽는 안내판 |
| 3 | `변경이력.md` 표 머리 | 첫 줄이 있어야 다음이 쌓인다 |
| 4 | 루트 `README.md`에 폴더·파일명 규칙 | 사람이 처음 보는 문 |

## 9. 요약 — 한 장으로

| 규칙 | 값어치 | 비고 |
|---|---|---|
| **CLAUDE.md 상시 컨텍스트** | ★★★ | 없으면 매 세션 맥락 설명에 시간을 다 쓴다 |
| **로그 3종 분리 (기각 이유 포함)** | ★★★ | 같은 논쟁 무한 반복을 막는 유일한 장치 |
| **설계 헌장 (어기려면 먼저 묻기)** | ★★★ | "하지 마라"를 안 적으면 AI가 계속 제안한다 |
| 파일명 `_vNN` 맨 뒤 | ★★ | 정렬이 곧 이력. 위반 0건으로 잘 지켜짐 |
| 폴더 번호 접두어 | ★★ | 정렬 순서를 내가 정하려고 |
| 폴더별 README | ★★ | 사람용이 아니라 **AI용 안내판** |
| main 푸시는 "배포" 말할 때만 | ★★ | 배포 사고 방지 |
| `.claude/skills` 한 단어 명령 | ★★ | 명령어를 외우지 않아도 됨 |
| `09_구버전` 이동 | ☆ | git이 대체함. 폴더만 남겨둘 것 |

> **한 줄로**: 폴더를 예쁘게 나누는 게 목적이 아니다.
> **기억을 잃는 협업자에게 매번 같은 맥락을 자동으로 넘기는 것**이 목적이고,
> 폴더·파일명은 그 목적의 가장 작은 부분이다.
