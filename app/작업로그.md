## [2026-08-17] 앞면 용어 누출 — 범인은 프롬프트 자신의 (O) 예시였다 (v138 · 0-f)

**배경**: 어제 A-3 에서 "샌 말이 전부 이미 금지 목록에 있으니, 목록 대신 **실측 누출 문장의 (X)→(O) 짝**을
박겠다"고 했다. 다른 세션이 **같은 60칸을 재실행**해 확인했는데:

| | 결과 |
|---|---|
| `direction=undefined` 가드 | 재발 **0** ✅ |
| 동률 오탐(A-4 하네스) | **소멸** ✅ |
| 은유 서술어 | 7 → **2** ✅ |
| **용어 누출** | 3 → **4** ❌ P7-Q17 은 같은 칸·같은 단어(「임오 대운」) 재발 |

**내 베팅이 절반 틀렸다.** 은유엔 먹혔고 용어엔 안 먹혔다.

### 왜 안 먹혔나 — 파 보니 규칙 문제가 아니었다

`SYS` 안에 이런 (O) 예시가 있었다:

> (O)"**무오 대운** — 앞으로 십 년, 불기운이 세지는 때야. 밀어붙이면 되는 판이지."

이건 **뒷면(reasons) 용 예시**고 뒷면은 용어를 써도 된다. 그런데 **`SYS` 는 콜1(앞면)·콜2(뒷면) 공용**이다.
모델은 이 (O) 를 앞면에도 적용한다 — 바로 위 줄에서 "verdict 에 대운을 한 글자도 쓰지 마라"고 해도 소용없다.
**모델은 규칙보다 예시를 따른다.** 이 리포가 이미 아는 원칙이고, 검사 5-g 가 그 원칙으로 만들어진 검사다.

**그런데 5-g 가 (O) 예시를 「은유」로만 재고 있었다.** 앞면 금칙어는 안 봤다.
원칙을 아는 것과 그 원칙을 **검사로 세우는 것**은 다른 일이었다.

### 세 겹으로 고쳤다

**① 예시에 층을 못 박고 앞면 대응쌍을 붙였다**
`(O)` → `(O·뒷면)`. 그리고 짝을 붙였다 — 짝 제시가 은유를 7→2 로 줄인 **바로 그 방식**이다:
> (X·앞면)"무오 대운이라 밀어붙일 때야" → (O·앞면)"앞으로 십 년은 밀어붙이면 되는 판이야."

콜2 지시문의 예시 목록에도 "이 용어들은 reasons 전용"을 붙였다.

**② 검사 5-g 확장 (= 0-f)**
층 표시 없는 (O) 가 앞면 금칙어를 담으면 **심각**. 규칙을 **원인이 있는 자리**에 놓았다 —
배분표가 요구한 "앞면 금칙어 정규식"을 출력이 아니라 **프롬프트 예시**에 건 이유다.
덤으로 **하네스(`eval/run-eval.mjs`)의 `JARGON` 과 목록이 문자열까지 같은지 대조**한다.
주석으로 "같다"고만 적어 두면 갈린다 — 갈리면 한쪽이 통과시킨 걸 다른 쪽이 잡고, **그 오탐이 진짜 실패를 가린다**(A-4 에서 겪었다).

**③ 런타임 계측 — `verdict_shown.jargon` / `detail_shown.sub_jargon`**
새 이벤트를 안 만들고 **분석이 이미 보는 이벤트에** 속성으로 붙였다.
이게 없으면 재발 여부를 알려면 **매번 API 키를 들고 평가를 돌려야 한다** — 이 세션엔 키가 없다.
⚠ **문장을 코드로 고치지는 않는다.** 앞면은 45자 한 문장이라 낱말을 들어내면 뜻이 깨진다.
고치는 건 프롬프트 몫이고, 코드 몫은 **샜다는 사실을 남기는 것**이다.

### 알고 남긴 구멍

**괘 이름(중수감·수뢰둔…)은 목록에 없어 안 잡힌다.** 실측으로 확인했다(subline 에 "중수감"을 넣어도 null).
넓히지 않은 이유 둘:
- 하네스가 **지금 이 목록으로** "용어노출 3→4"를 세고 있다. 중간에 바꾸면 **판이 서로 비교가 안 된다.**
- 지금은 `COIN_RITUAL=false` 라 주역 축이 프롬프트에 안 들어가서 **괘 이름이 나올 경로가 없다.**

동전을 되살리는 날 **양쪽 목록을 같이** 넓힐 것 — 코드 주석에 남겼다.

## [2026-08-17] 곁에 이름이 붙었다 — 그리고 그 이름을 기기 안에 가뒀다 (v136)

**지시(창업자)**: *"곁 탭 최초 진입한 사람은 궁합 볼 사람의 이름을 쓰게 하고, 한 번 쓴 사람은 두 번을
클릭해야 이름 목록을 볼 수 있게. 마치 판결 탭처럼. 두 번 탭 하면 써머리로 그래프와 표, 그 밑에 리스트.
그리고 이 정보가 판결 탭에도 흘러가게 — 내 사업에 도움이 될 사람이 있을까? 했을 때."*

### 내가 반대했고, 근거가 틀렸다

직전 턴에 **"이름은 독"**이라고 답했다. 근거 셋 — ①엔진이 안 쓴다 ②목록이 사람 명부가 된다
③역산에 얼굴이 붙는다. 창업자가 든 반례는 **관찰**이었다: 도령에서 사람들은 심부름인 줄 알면서도
이름을 넣는다. *나와 저 사람이 어떤 관계인지가 궁금해서*다.

내 ①은 **엔진 기준**이었다. 유저 기준으로 이름은 계산에 쓰는 값이 아니라 **"누가 누구인지"**다.
곁이 넷만 되어도 오행 점 네 개는 서로 구별이 안 된다 — 이름이 없으면 목록이 아니라 얼룩이다.
②③은 여전히 유효한 위험이라 **없애는 대신 조건으로 바꿨다**(아래).

### 지킨 선 — 이름은 기기 밖으로 한 걸음도 안 나간다

| 어디 | 어떻게 |
|---|---|
| AI | **이름 대신 `곁1`·`곁2` 자리표 + 역할 이름**만 보낸다. 돌아온 문장에서 앱이 기기 안에서 바꾼다 |
| 계측 | 이름 0. 「적었는지 여부」(`named:true`)만 센다 |
| 서버 | 명부를 보내는 배선이 애초에 없다 |
| 공유·부적 | 자리표를 「곁에 선 사람」 가림말로 — **곁은 미동의 제3자다** |
| 계산 | 이름은 안 쓴다. 비워도 궁합·역할이 그대로 나온다 |

⚠️ **처음엔 `r1.verdict` 를 직접 이름으로 바꿨다가 되돌렸다.** r1 은 밖으로 나가는 길을 **전부** 탄다 —
`convo`(다음 턴 프롬프트) · `v_anon`(PostHog) · `explainMsg`(콜2) · 공유 페이로드 · 서신(콜3).
한 줄 바꾸면 다섯 곳으로 동시에 샌다. 그리고 화면 바로 아래에 "서버로도 통계로도 안 나가"라고
적어 놨으므로, 그건 **v127.7 과 같은 종류의 사고**가 된다 — 약속을 먼저 쓰고 코드가 안 따라간 것.
치환은 **화면과 기기 저장에서만** 한다.

### 만든 것

- **명부 스키마**: `name`(기기 전용, 12자) + `dg`(상대 일간 0~9 — 역할 10종을 세는 데 쓴다).

## 2026-08-31 · CSS 블록 백틱 — 같은 실수 세 번째, 이번엔 검사를 세웠다

App.jsx 의 스타일은 템플릿 리터럴(`const CSS = \`…\``) 안에 산다. 주석에 백틱을 하나 쓰면
문자열이 그 자리에서 끊겨 빌드가 죽는다. **오늘까지 세 번 했다** — 홀로 오버라이드 때 한 번,
빈 자리 칸 때 한 번, 곁 카드 뒷면 때 한 번.

빌드가 잡아 주긴 한다. 문제는 **메시지가 원인과 멀다**는 것이다 —
「Expected ";" but found "li"」가 뜨고, 그 줄에는 백틱이 안 보인다(끊긴 자리는 위쪽이다).
매번 처음부터 추적하게 된다.

→ `e2e/css-backtick-check.mjs` 신설. **값이 아니라 성질을 묻는다** — 「CSS 블록 안에 백틱이 있는가」.
   일부러 하나 넣어 FAIL 이 나는 것까지 확인하고 되돌렸다(검사가 실제로 무는지 확인 안 하면
   검사가 아니라 장식이다).
→ 규칙: **CSS 주석에서 코드 이름을 감쌀 때 백틱을 쓰지 마라.** 맨 글자로 쓴다.
