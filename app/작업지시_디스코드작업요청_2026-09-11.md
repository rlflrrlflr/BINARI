# 디스코드에서 작업을 시킨다 — 배선과 손으로 할 설정

> 2026-09-11 작성. 창업자 지시: *"디스코드로 명령하고, 깃허브에서 실제로 돌게하는건? … 우선 실행해."*
>
> **코드는 다 들어갔다. 남은 건 사장님이 화면에서 값 네 개를 넣는 것뿐이다.**
> 값을 안 넣으면 입구는 **닫힌 채로 있다**(아무도 못 시킨다) — 배포해도 위험하지 않다.

---

## 0. 왜 이걸 만들었나 — 문제는 도구가 아니라 피드백이 안 닫히는 것이었다

창업자 진단: *"다른 팀원들이랑 협업을 하려고 하는데, 실제로 뭘 할 수 있는지 뭘해야하는지 본인들이 몰라.
고친다고하면 그게 반영이 되는지 이런게 안되니까"*

셋은 서로 다른 문제이고 **디스코드가 푸는 건 그중 하나뿐이다.**

| 문제 | 디스코드가 푸나 | 여기서 다루나 |
|---|---|---|
| 뭘 할 수 있는지 모른다 | 부분 — 남이 시키는 걸 보면 배운다 | ○ (슬래시 명령이 곧 예시가 된다) |
| 뭘 해야 하는지 모른다 | **아니다** — 채팅은 흘러간다 | ✗ **안 흘러가는 목록이 따로 필요하다(미결)** |
| 고친 게 반영되는지 모른다 | **그렇다** | ○ (`deploy-notify.yml`) |

⚠ **그래서 이 지시서로 협업 문제가 다 풀리지 않는다.** 두 번째 칸은 채팅으로 못 푼다.
팀이 폰으로 열어 보는 **목록 한 장**이 따로 있어야 한다 — 아직 안 만들었다.

⚠ **그리고 이게 왜 급해졌나**: 2026-09-10 에 유료 광고를 로드맵에서 뺐다(창업자 결정).
그 뒤로 **팀의 손이 유일한 성장 수단**이다. 팀이 말을 걸지 않으면 엔진이 멈춘다.
정본은 `CLAUDE.md` §현재 전략 상태 의 「획득은 유료 광고 없이 간다」와 `결정필요사항_v01` §결정 1.

## 1. 흐름

```
 디스코드 슬래시 명령
   /시켜 일:"곁 지우기 확인창 넣어줘"
        │
        ▼
 app/api/discord.js          ← Vercel. 문패만 확인하고 넘긴다(일을 안 한다)
   · Ed25519 서명 확인
   · 허용된 사람인가
   · 깃허브를 깨운다 (repository_dispatch: discord-task)
        │
        ▼
 .github/workflows/claude-task.yml
   · 브랜치를 새로 딴다 (claude/discord-<run_id>)
   · 클로드가 고친다 (구독 로그인 — 토큰 과금 없음)
   · health-check 통과 확인
   · 커밋·푸시·PR
        │
        ▼
 디스코드 웹훅으로 결과
   "다 했어요 / 바꾼 건 없어요 / 막혔어요" + 볼 곳 링크
```

**왜 Vercel 이 중간에 있나**: 디스코드는 정해진 주소로 POST 하는데 깃허브 액션은 그 POST 를
직접 못 받는다(액션은 깃허브 API 로 깨워야 한다). 중간 서버가 하나 필요한데 **이미 Vercel 을 쓰고
있어서 컴퓨터를 새로 켜둘 필요가 없다.** 그게 유일한 이유다.

**왜 main 에 직접 안 올리나**: 디스코드 한 줄이 곧바로 라이브를 바꾸면 오타 한 번에 유저 화면이
깨진다. 항상 브랜치 + PR 로 멈추고 사람이 합친다. `CLAUDE.md` 의 「main 푸시는 명시 지시가 있을
때만」과 같은 뜻이다.

## 2. 사장님이 손으로 할 것 (네 개)

### ① 디스코드 앱 만들기 — 5분

1. <https://discord.com/developers/applications> → **New Application** (이름: 비나리)
2. 좌측 **General Information** → **Public Key** 를 복사한다 → ③에서 쓴다
3. 좌측 **Bot** → 봇을 만들고, **Installation** 에서 우리 서버에 넣는다
4. 좌측 **General Information** → **Interactions Endpoint URL** 에 아래를 넣고 저장

```
https://binari-sepia.vercel.app/api/discord
```

⚠ **저장을 누르면 디스코드가 일부러 틀린 서명을 보내 시험한다.** 우리가 401 로 막아야 통과한다.
막는 코드는 이미 들어 있고 `e2e/discord-check.mjs` 가 그걸 검사한다.
⚠ 단 ③의 Public Key 를 Vercel 에 먼저 넣어야 이 저장이 성공한다. **순서가 ③ → ① 이다.**

### ② 슬래시 명령 만들기 — 3분

디스코드 개발자 화면에는 명령 등록 버튼이 없다. 한 번만 아래를 실행한다
(`<봇토큰>`·`<앱ID>` 는 개발자 화면에서 복사).

```bash
curl -X POST \
  -H "Authorization: Bot <봇토큰>" \
  -H "Content-Type: application/json" \
  -d '{"name":"시켜","description":"클로드에게 작업을 시킨다","options":[{"name":"일","description":"무엇을 해야 하나","type":3,"required":true}]}' \
  "https://discord.com/api/v10/applications/<앱ID>/commands"
```

### ③ Vercel 환경변수 세 개 — 3분

Vercel → binari 프로젝트 → Settings → Environment Variables.
**넣고 나서 수동 Redeploy 를 해야 적용된다**(`CLAUDE.md` 운영 규칙).

| 이름 | 값 | 없으면 |
|---|---|---|
| `DISCORD_PUBLIC_KEY` | ①에서 복사한 Public Key | 입구가 500 으로 닫힌다 |
| `GITHUB_DISPATCH_TOKEN` | 아래 설명 | 「시작을 못 했어요」가 뜬다 |
| `DISCORD_ALLOWED_USERS` | 사장님 디스코드 사용자 ID | **아무도 못 시킨다(닫힘이 기본)** |

`GITHUB_DISPATCH_TOKEN` 만들기: GitHub → Settings → Developer settings →
**Fine-grained tokens** → 이 저장소만 선택 → 권한 **Contents: Read and write** 와
**Metadata: Read**. (`repository_dispatch` 는 Contents 쓰기 권한으로 부른다.)

사용자 ID 얻기: 디스코드 설정 → 고급 → **개발자 모드** 켜고, 내 이름 우클릭 → **사용자 ID 복사**.

⚠ **사람 ID 로 막는다.** 채널로만 막으면 그 채널에 초대된 누구나 코드를 돌릴 수 있다.
채널 제한은 덧문이고 선택이다(`DISCORD_ALLOWED_CHANNEL`).
팀원에게 열어 줄 때는 쉼표로 이어 붙인다 — `111,222,333`.

### ④ 깃허브 비밀값 하나 — 2분

저장소 → Settings → Secrets and variables → **Actions** → New repository secret.

| 이름 | 값 |
|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | 내 컴퓨터에서 `claude setup-token` 을 돌려 받은 값 |

`DISCORD_WEBHOOK_URL` 은 **이미 있다** — 아침 지표가 쓰는 값을 그대로 쓴다.

⚠ **이 토큰이 구독 계정 것이라 토큰 과금이 안 붙는다.** 대신 **구독 사용 한도**를 함께 쓴다.
여러 명이 동시에 시키면 한도가 빨리 준다. `claude-task.yml` 이 한 번에 하나만 돌게 막아 두었고
(`concurrency`) 한 작업을 30분에서 끊는다.
⚠ 구독으로 자동화를 돌리는 것의 정확한 한도·약관은 **리포에서 확인할 수 없다.** 붙이기 전에
계정 요금 화면에서 한 번 본다.

## 3. 비용 — 지금 구성은 추가 지출 0원이다

| 무엇 | 얼마 | 주의 |
|---|---|---|
| 디스코드 | 0원 | 서버·봇·웹훅 전부 무료 |
| Vercel 함수 | 0원 | 이미 쓰는 프로젝트에 파일 하나 추가일 뿐 |
| 깃허브 실행 | 0원 | **공개 저장소는 무제한 무료** |
| 클로드 | 0원 | 구독 로그인 — 토큰 과금 없음 |

⚠ **저장소를 비공개로 바꾸면 깃허브 실행에 무료 한도가 생긴다.** 무료 계정 기준 월 2,000분
수준이고(요금 페이지에서 확인 필요), 작업 한 번이 5~15분이니 하루 다섯 번이면 아슬아슬하다.
넘으면 분당 과금 — 월 만원 안팎으로 추정.
→ **창업자 판단(2026-09-11): 트라이얼 단계라 공개 유지, 전환은 나중에.** 전환하는 날 이 칸을 다시 본다.

⚠ API 로 돌리면(구독 대신) 오늘 수준의 작업을 하루 다섯 번 잡아 **월 10만~60만원대로 추정**된다.
추정이고 작업 크기에 크게 흔들린다. 트라이얼 단계에서 쓸 이유가 없다.

## 4. 무엇을 시킬 수 있고 무엇을 못 시키나

**된다** — 코드 고치기, 검사 돌리기, 문서 쓰기, 계측 붙이기, 문구 바꾸기.
이 저장소의 검사 체계(검진 125칸 + 화면 검사들)가 채점기 구실을 하므로 기계가 스스로 맞는지 안다.

**안 된다** — 「이 문구가 마음에 꽂히나」, 「이 색이 예쁜가」. 기계가 채점할 수 없는 것.
판결 248건 사람 채점이 아직 팀 손에 남아 있는 이유가 이것이고, **에이전트를 늘려도 안 풀린다.**

**느리다** — 한 번에 몇 분. 채팅처럼 즉답이 아니다.

**애매하면 멈춘다** — 요청이 여러 갈래로 읽히면 추측해서 고치지 말고 무엇이 애매한지 적고 멈추게
해 뒀다. 물어볼 사람이 그 자리에 없으므로 **잘못 짚고 진행하는 것보다 멈추는 게 싸다.**

## 5. 검사

`e2e/discord-check.mjs` 13칸. **값이 아니라 성질을 묻는다** — 서명 없으면 막는가 / 본문이 바뀌면
막는가 / 허용 목록이 비면 아무도 못 시키는가 / 허용된 사람은 깃허브를 깨우는 자리까지 가는가 /
거절할 때 목록을 흘리지 않는가.

`health-check` **5-r 로 실행 목록에 올렸다.** 이 리포가 반복해서 부딪힌 함정이
「검사는 있었는데 검진이 안 불렀다」라서(8/31 라이브 사고·9/4 미리보기 순서 사고) 신설과 등재를
한 호흡에 묶는다.

서버·브라우저가 필요 없다(핸들러를 직접 불러 검사한다). 실행: `node app/e2e/discord-check.mjs`

## 6. 남은 것

1. 🔴 **팀이 폰으로 여는 목록 한 장** — 「뭘 해야 하는지 모른다」는 채팅으로 안 풀린다.
   세 칸이면 된다: 부탁할 수 있는 것 / 비어 있는 일 / 내 의견이 어떻게 됐나(기각도 이유와 함께).
2. **팀원 열어 주기** — 지금은 사장님만. `DISCORD_ALLOWED_USERS` 에 ID 를 이어 붙인다.
   ⚠ 열기 전에 생각할 것: 팀원이 시킨 작업도 PR 로 멈추지만, **구독 한도를 같이 쓴다.**
3. **자기 초대 문제와 같은 계열의 미결** — 사장님 계정이 털리면 저장소에서 코드가 돈다.
   디스코드 2단계 인증을 켜는 것이 지금 할 수 있는 최선이다.
