# 채널마다 따로 시킨다 + 봇끼리 얘기할 자리를 만든다 — 브라우저에서 할 일

> 2026-09-21 작성. 창업자 지시: *"채널별로 따로 작업요청할 수 있도록 크롬 확장자 클로드에게
> 작업요청할 요청서 작성 / 더불어, 봇끼리 대화할 수 있는 채널 별도 개설할 수 있는 요청서도 포함"*
>
> **이 문서의 알맹이는 §3·§4 의 요청서 두 장이다.** 통째로 복사해 크롬 확장 클로드에게 준다.
> 나머지는 왜 이렇게 하는지 — 다음 세션이 읽는 부분이다.

---

## 0. 왜 AI 가 직접 못 하고 요청서를 쓰나

디스코드 **서버 설정**과 Vercel **환경변수**는 사장님 계정으로 로그인한 브라우저에서만 만져진다.
이 세션은 저장소와 깃허브 API 까지만 닿는다 — `api.vercel.com` 은 이 환경에서 막혀 있고,
디스코드 채널 권한은 애초에 우리가 가진 봇 토큰으로 못 바꾼다(봇이 자기 권한을 스스로 올릴 수 없다).

그래서 **브라우저를 모는 손**이 따로 필요하고, 크롬 확장 클로드가 그 손이다.

⚠ **요청서는 저장소를 못 보는 상대가 혼자 읽고 끝까지 갈 수 있게 쓴다.** 그쪽에는 이 파일도,
`CLAUDE.md` 도, 실행 기록도 없다. 그래서 §3·§4 는 이 저장소 어휘(분모 100·이중 필터 따위)를
한 번도 쓰지 않고, 화면에 실제로 보이는 이름으로만 적었다.

⚠ **요청서에 비밀값을 읽으라고 시키지 않는다.** 남의 브라우저를 모는 상대에게 「토큰을 확인해 줘」라고
하면 그 값이 대화에 남는다. 그래서 전부 **「이름이 목록에 있는지」만** 묻는다.

## 1. 지금 무엇이 막고 있나 — 둘이고, 성질이 다르다

| 막는 것 | 어떻게 드러나나 | 확실한가 |
|---|---|---|
| ① 봇이 그 채널에 못 쓴다 | 시킨 채널이 아니라 **데이터 채널**에 결과가 뜬다 | **실측** — 9/15 실행 기록에 `403 Forbidden` 뒤 「웹훅 채널로 보낸다」 |
| ② 명령 자체가 한 채널에서만 먹는다 | 다른 채널에서는 *"여기서는 작업을 시킬 수 없어요"* 가 뜬다 | **미확인** — Vercel 값이라 이 세션에서 못 본다 |

①은 고치는 법이 정해져 있다(권한 켜기). ②는 **있는지부터 봐야 한다** —
`DISCORD_ALLOWED_CHANNEL` 이라는 덧문이 켜져 있으면 권한을 아무리 열어도 다른 채널에서는 시작조차 안 된다.
요청서 ①이 둘을 한 번에 훑는 이유다.

⚠ **②를 안 보고 ①만 고치면 「고쳤는데 여전히 안 된다」가 된다.** 그러면 원인이 셋으로 갈리고
(권한·덧문·코드) 왕복이 길어진다. 한 번에 둘 다 본다.

## 2. 같이 넣은 것 — 채널 점검 버튼

`.github/workflows/discord-channel-check.yml` (신설). Actions 탭에서 채널 ID 를 넣고 돌리면
**봇이 그 채널에 글 한 줄을 써 본다.** 되면 ○, 안 되면 ✗ 와 이유(403 권한 / 404 봇이 서버에 없음 / 401 토큰).

**왜 만들었나**: 지금까지 「봇이 이 채널에 쓸 수 있나」를 알려면 작업을 **통째로 한 번 돌려야** 했다.
클로드가 몇 분 일하고 맨 끝에 가서야 권한 없음이 드러난다 — 구독 한도를 태우고 얻는 답이다.
권한 설정은 한 번에 맞는 일이 드물어서 그 왕복이 여러 번 생긴다.
이 버튼은 클로드를 안 부르고 몇 초에 끝난다. **한도를 안 쓴다.**

⚠ **「쓸 수 있나」를 물어보는 창구가 디스코드에 없다.** 그래서 실제로 써 본다 —
그게 이 검사가 정직한 이유이고, 채널에 한 줄이 남는 이유다. 조용하지만 아무것도 확인 못 하는 검사는
이 저장소가 반복해서 데인 함정이다(8/31 라이브 사고·9/4 미리보기 순서 사고).

⚠ 보내는 길은 늘리지 않았다. `app/tools/discord-post.py` 를 경로로 불러들여 쓴다 —
User-Agent 가 한 곳에만 있어야 같은 403 을 네 번째로 밟지 않는다.

## 3. 요청서 ① — 채널마다 따로 시킬 수 있게 (아래를 통째로 복사)

```
비나리 팀 디스코드 서버와 Vercel 설정을 손봐 줘. 내 계정으로 로그인된 브라우저에서 해 줘.

[배경 — 알고 있어야 하는 것]
· 비나리라는 사이드 프로젝트의 팀 디스코드 서버가 있고, 거기에 "비나리" 봇이 들어와 있어.
· 그 봇에게 /콜 이라는 슬래시 명령으로 개발 작업을 시키면, 깃허브에서 AI가 코드를 고치고
  결과를 디스코드로 돌려줘.
· 지금 문제: 어느 채널에서 시키든 결과가 항상 「데이터」 채널에만 떠. 봇이 다른 채널에
  글을 쓸 권한이 없어서야.
· 채널은 다섯 개: 데이터 · 디자인 · 로직 · 비즈니스 · 작업로그

[목표]
다섯 채널 어디서 시켜도 그 채널에 결과가 오게 만들기.

[지켜야 할 것 — 중요]
· 토큰·비밀값·API 키의 값을 열어보거나 나에게 붙여넣지 마. "있다/없다"만 말해 줘.
· 아래 적힌 것 외에는 아무것도 바꾸지 마. 특히 사람 권한, 다른 봇, 역할 순서,
  채널 삭제나 이름 변경은 건드리지 마.
· 누구도 초대하거나 추방하지 마.
· 화면이 아래 설명과 다르면 멈추고 무엇이 다른지 말해 줘.
  비슷해 보이는 버튼을 추측해서 누르지 마.

[할 일]

1) 디스코드에서 개발자 모드를 켠다
   사용자 설정(왼쪽 아래 톱니) → 고급 → 개발자 모드 켜기.
   (채널 ID를 복사하려면 이게 켜져 있어야 해)

2) 봇 역할에 기본 권한을 준다
   서버 이름 클릭 → 서버 설정 → 역할 → 봇 이름으로 된 역할(대개 "비나리")을 연다
   → 권한 목록에서 다음 셋을 켜고 저장:
      · 채널 보기
      · 메시지 보내기
      · 링크 첨부

3) 채널 다섯 곳을 하나씩 확인한다 (데이터 · 디자인 · 로직 · 비즈니스 · 작업로그)
   채널 이름에 마우스를 올리고 톱니(채널 편집) → 권한
   · "비공개 채널"이 켜져 있으면: 멤버 또는 역할 추가 → 봇 역할을 추가 →
     "채널 보기" 체크, "메시지 보내기" 체크 → 저장
   · "메시지 보내기"가 빨간 X로 막혀 있으면 체크로 바꾸고 저장
   · 이미 되어 있으면 그대로 두고 넘어가

4) 채널 ID 다섯 개를 모은다
   각 채널 이름 우클릭 → "채널 ID 복사"
   → "채널이름: 숫자" 형태로 다섯 줄 목록을 만들어서 나에게 줘.

5) Vercel 설정을 확인한다
   vercel.com → binari 프로젝트 → Settings → Environment Variables
   · DISCORD_ALLOWED_CHANNEL 이라는 항목이 있는지 봐.
     있고 값이 채워져 있으면 그 항목을 삭제해 줘.
     (한 채널에서만 명령이 먹게 막는 항목이야. 지금은 다섯 곳 다 열어야 해.)
   · DISCORD_PUBLIC_KEY / GITHUB_DISPATCH_TOKEN / DISCORD_ALLOWED_USERS
     이 세 항목이 목록에 있는지만 확인해서 알려 줘. 값은 열어보지 마.
   · 무언가 지웠거나 바꿨으면 반드시:
     Deployments 탭 → 맨 위 배포 → 점 세 개 → Redeploy
     (이걸 안 하면 바꾼 게 적용되지 않아)

6) 깃허브 설정을 확인한다
   github.com/rlflrrlflr/BINARI → Settings → Secrets and variables → Actions
   · DISCORD_BOT_TOKEN / CLAUDE_CODE_OAUTH_TOKEN / DISCORD_WEBHOOK_URL
     이 세 개가 이름만이라도 목록에 있는지 확인해서 알려 줘.
     값은 볼 수 없고 볼 필요도 없어.

7) 실제로 되는지 확인한다
   github.com/rlflrrlflr/BINARI → Actions 탭
   → 왼쪽 목록에서 "디스코드 채널 점검" → 오른쪽 "Run workflow"
   → 첫 칸에 4)에서 모은 채널 ID 다섯 개를 쉼표로 이어서 붙여넣고 실행
   → 1~2분 뒤 실행 결과를 열어서, 어느 채널이 ○ 이고 어느 채널이 ✗ 인지 알려 줘.
   → ✗ 가 있으면 그 채널에 대해 2)와 3)을 다시 하고 한 번 더 돌려.

[다 끝나면 알려 줄 것]
· 채널 이름과 ID 다섯 줄
· Vercel 에 DISCORD_ALLOWED_CHANNEL 이 있었는지, 지웠는지
· 5)와 6)에서 확인한 항목들이 있었는지 (있다/없다만)
· 채널 점검 결과 (○/✗)
```

## 4. 요청서 ② — 봇끼리 얘기할 채널 만들기 (아래를 통째로 복사)

```
비나리 팀 디스코드 서버에 채널을 하나 새로 만들어 줘. 내 계정으로 로그인된 브라우저에서 해 줘.

[무엇을 위한 채널인가]
AI 둘이 서로 주고받으면서 개발하게 할 거야. 한 쪽이 고치면 다른 쪽이
"이러면 망가진다"를 찾는 식이야. 그 주고받는 내용을 사람이 볼 수 있게 방을 따로 판다.
기존 다섯 채널(데이터·디자인·로직·비즈니스·작업로그)에 섞이면 사람 대화가 묻혀.

[지켜야 할 것]
· 기존 채널·역할·사람 권한은 아무것도 건드리지 마. 새 채널만 만들어.
· 토큰이나 비밀값의 값을 열어보거나 나에게 붙여넣지 마.
· 화면이 설명과 다르면 멈추고 무엇이 다른지 말해 줘.

[할 일]

1) 채널을 만든다
   채널 목록 위의 + 또는 서버 설정 → 채널 → 채널 만들기
   · 종류: 텍스트 채널
   · 이름: 에이전트-회의
   · 비공개 채널: 끔 (팀 전원이 볼 수 있게)

2) 채널 주제(설명)를 넣는다
   채널 톱니(편집) → 개요 → "채널 주제" 칸에 아래 문장을 넣고 저장:
   AI 들이 서로 주고받는 자리입니다. 사람이 끼어들어도 됩니다.
   여기서 나온 결론은 그대로 반영되지 않고, 항상 사람이 확인하는 단계를 거칩니다.

3) 봇이 여기 쓸 수 있게 한다
   같은 편집 화면 → 권한 → 봇 역할(대개 "비나리")에
   "채널 보기" 체크, "메시지 보내기" 체크 → 저장

4) 알림이 폭탄이 되지 않게 한다
   서버 설정 → 개요 → "기본 알림 설정"을 확인해 줘.
   "모든 메시지"로 되어 있으면 "@멘션만"으로 바꿔 줘.
   (AI 가 주고받으면 한 번에 여러 줄이 올라와. "모든 메시지"면 팀 전원 폰이 계속 울려)
   원래 무엇이었는지도 알려 줘.

5) 채널 ID 를 깃허브에 등록한다
   · 새 채널 우클릭 → "채널 ID 복사"
   · github.com/rlflrrlflr/BINARI → Settings → Secrets and variables → Actions
   · 위쪽 탭에서 "Variables"를 고른다 (Secrets 아님!)
   · New repository variable
     Name: DISCORD_AGENT_CHANNEL_ID
     Value: 방금 복사한 숫자
   ※ Secrets 가 아니라 Variables 인 이유: 채널 ID 는 비밀이 아니라 그냥 주소야.
     비밀로 가려 두면 나중에 문제가 생겼을 때 실행 기록에서 못 들여다봐.

6) 되는지 확인한다
   Actions 탭 → "디스코드 채널 점검" → Run workflow
   → 첫 칸에 새 채널 ID 하나만 넣고 실행
   → 새 채널에 점검 메시지가 뜨면 성공. 결과를 알려 줘.

[다 끝나면 알려 줄 것]
· 만든 채널 이름과 ID
· 기본 알림 설정이 원래 무엇이었고 지금 무엇인지
· 점검 결과
```

⚠ **이 요청서는 방만 판다. 봇끼리 주고받는 코드는 아직 안 짰다.** 방을 파는 건 공짜이고
되돌리기도 쉬워서 먼저 해 둬도 손해가 없지만, 실제로 둘을 돌리는 건 §6 의 결정이 나온 뒤다.

## 5. 요청서가 끝나면 이쪽에서 할 일

1. **채널 ID 다섯 개를 받아 이 문서에 적는다.** 비밀이 아니다 — 공개 실행 기록에 이미 남는다
   (9/15 기록에 디자인 채널 `1549238305818939432` 가 그대로 찍혀 있다).
   적어 두면 다음 세션이 권한 문제를 만났을 때 바로 점검을 돌릴 수 있다.
2. **`DISCORD_ALLOWED_CHANNEL` 이 있었는지에 따라 §1 의 ②가 사실이 된다.** 있었으면
   「다른 채널에서 시작조차 안 됐다」가 확정이고, 없었으면 원인은 권한 하나뿐이었다는 뜻이다.
   **둘 중 무엇이었는지 반드시 기록한다** — 추측으로 남기면 다음에 또 셋을 뒤진다.
3. 봇 대화 루프는 §6 결정 뒤에 짠다.

## 6. 아직 안 정한 것 (창업자 결정 대기)

봇끼리 주고받게 할지, 어떻게 할지는 아직 결정이 안 났다. 2026-09-21 대화에서 이렇게 제시했다.

- **언제 만드나** — 지금 / 나중. 지금 안 만들면 팀은 계속 한 번에 한 마디씩만 시킬 수 있다.
  단 **순서상 채널 권한이 먼저다** — 지금 만들면 대화가 전부 데이터 채널에 쌓인다.
- **배역을 몇으로 하나** — 둘(만드는 쪽·깨는 쪽)이 안전하고, 넷(채널별: 로직·데이터·디자인·비즈니스)은
  재미있지만 한 판에 네 턴이라 구독 한도를 네 배로 먹는다. **둘을 권했다.**

**설계상 못 박을 것 셋** (만들기로 하면 그대로 넣는다):

1. **라운드 상한 4.** 둘이 신나면 스무 번을 주고받고 그날 사장님 몫이 없어진다.
2. **검진을 통과하면 남은 라운드가 있어도 즉시 종료.** 심판이 사람이 아니라 검사 프로그램이어야
