# 작업지시 — 색장에 없는 연출 셋 (벼름 · 낙착 일렁임 · 정독 저프레임)

받는 곳: **색장(홀로 수호신)을 쥐고 있는 세션**
작성 2026-08-31 · 근거: `brood-check` 8/10 실패 + 코드 확인

> 읽기 전에 `git fetch origin main`. 좌표는 **함수명·문자열**로 적었다 — 줄번호는 하루에도 여러 번 밀린다.

## 1. 한 줄

**기본 스킨이 홀로로 뒤집히면서, 옛 판(입자 렌더러)에만 있던 연출 셋이 기본 화면에서 통째로 사라졌다.**
빠뜨린 게 아니라 `GuardianField` 에 **처음부터 구현이 없다.**

## 2. 사라진 셋

| 연출 | 무엇이었나 | 신호원 |
|---|---|---|
| **벼름** | 판결을 기다리는 동안 존재가 **가라앉는다**. 답이 오면 다시 뜬다 | `broodRef` |
| **낙착 일렁임** | 동전이 떨어질 때마다, 판결이 확정될 때마다 존재가 **한 번 일렁인다** | `agitateRef` |
| **정독 저프레임** | 카드를 읽는 동안 캔버스를 **사실상 정지**시켜 메인스레드와 배터리를 양보한다(3단계 0/46/300ms) | `restRef` |

## 3. 확인한 사실 (추측 아님)

- 셋 다 `GuardianCanvasGL` 에는 **구현돼 있다** — `bWant = broodRef && broodRef.current ? 1 : 0` 으로 목표를 잡고 부드럽게 따라가는 코드까지 있다(들어갈 땐 1.1초, 풀릴 땐 0.35초).
- `GuardianField` 구간에는 `brood` · `agitate` · `restRef` 문자열이 **0건**이다.
- `Guardian` 이 `GuardianField` 에 넘기는 prop 은 `saju · mood · orbRef · reactRef · scatter · size · gyeotRef · popRef · onFail` 뿐이다 — 셋이 애초에 안 넘어간다.
- **prop 만 넘겨도 아무 일도 안 일어난다.** 받는 쪽이 없다.

## 4. 지금 검사가 이렇게 말한다

```
FAIL — ② 가라앉는다(평상시 흔들림 범위를 벗어나 내려감) · 평상시 최저점 0.544 → 벼름 0.477
FAIL — ④ reduced-motion 이면 가라앉지 않는다 · 중심 0.435
=== 판결 대기 연출: 8/10 PASS ===
```

`brood-check.mjs` 는 **밝기 신호로 성질을 잰다** — 「평상시 흔들림 범위를 벗어나 내려가는가」. 그래서
**셰이더로 어떻게 구현하든 이 검사가 그대로 유효하다.** 값을 맞추려 하지 말고 성질을 만들면 된다.

## 5. 부탁

1. 셋을 색장에 구현한다. `GuardianCanvasGL` 의 벼름 코드가 **의도의 정본**이다 — 시간 상수(1.1s / 0.35s)와 비대칭(들어갈 땐 느리게, 풀릴 땐 빠르게)이 거기 적혀 있다.
2. `Guardian` → `GuardianField` prop 에 `broodRef` · `agitateRef` · `restRef` 를 더한다.
3. **`reduced-motion` 을 지킨다.** `broodRef.current = busy && !reduce` 로 이미 걸러서 넘어온다 — 색장에서 그 값을 무시하지 마라. 검사 ④가 이걸 문다.
4. **정독 저프레임은 배터리 문제다.** 카드를 읽는 동안 전면 사각형 셰이더가 60fps 로 계속 돈다. 눈에 안 보이는 연출이라 제일 잊기 쉬운데, 실기 체감에 제일 크게 걸린다.

## 6. 안 건드릴 것

- **입자 렌더러(`GuardianCanvasGL`/`Sim`/2d)를 지우지 마라.** 폴백이자 `?skin=dark` 의 본체다. 2026-08-31 에 **첫 방문자가 빈 화면을 보는 사고**가 났을 때 유일한 생존자가 그쪽이었다(`변경이력.md` 같은 날 v179.1).
- `canHolo` 판별식(못 그릴 기기에 홀로를 안 주는 곳)과 `NO_SAJU` 채움값은 그 사고의 수습이다. 손대려면 `webgl-check ⓪` 을 먼저 읽어라.
